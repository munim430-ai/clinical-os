## 2024-06-25 - [Explicit Accessibility Attributes for Custom React Native Components]
**Learning:** Custom interactive components (like `Pressable` wrapping a `View`) in React Native do not inherently communicate their purpose or state to screen readers. For example, the `AIOrbButton` relied purely on visual cues (colors, shadows) and context to indicate it was an interactive button with an active/expanded state.
**Action:** Always add `accessibilityRole="button"`, a descriptive `accessibilityLabel`, and explicitly manage state via `accessibilityState={{ expanded: isActive }}` for custom button implementations to ensure they are fully usable by assistive technologies. Additionally, ensure `hitSlop` is explicitly defined (e.g., `{ top: 10, bottom: 10, left: 10, right: 10 }`) to provide an adequate touch target area.
